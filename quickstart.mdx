# Quickstart Guide

This guide will walk you through your first session with SIGSAHO, from logging in to navigating the dashboard and performing your first operational task.

<Note>
  Your system administrator should have provided you with login credentials. If you don't have an account yet, contact your admin.
</Note>

## Prerequisites

Before you begin, ensure you have:

- Login credentials (username or email + password)
- Modern web browser (Chrome, Firefox, Safari, or Edge)
- Stable internet connection
- Your assigned role permissions

---

## Step 1: Access the Platform

Navigate to your organization's SIGSAHO instance. The login screen will greet you with a clean, professional interface.

<Steps>
  <Step title="Open SIGSAHO">
    Enter the URL provided by your administrator (e.g., `https://sigsaho.yourcompany.com`)
  </Step>
  <Step title="Enter Credentials">
    Input your username or email and password
  </Step>
  <Step title="Optional: Remember Session">
    Check "Mantener sesión activa" to stay logged in on trusted devices
  </Step>
</Steps>

### Login Form Example

The authentication system uses secure httpOnly cookies for session management:


## Step 4: Your First Task

Let's complete a common task based on your role. Here are quickstart guides for each role:

<Tabs>
  <Tab title="Dispatcher">
    ### Check Aircraft Status
    
    <Steps>
      <Step title="Navigate to Fleet">
        Click **Despacho** → **Flota** in the sidebar

      <Step title="Select Aircraft">
        Choose an aircraft (e.g., Bell-407, Cessna-208)
      </Step>
      <Step title="Review Details">
        View current flight hours, maintenance status, and next service due

    ```typescript

      matricula: string;        // Registration (e.g., "XA-UPQ")
      modelo: string;           // Model
      horas_totales: number;    // Total flight hours
      proximo_servicio: string; // Next maintenance date
      estado: 'OPERATIVA' | 'MANTENIMIENTO' | 'INACTIVA';
    }
    ```
  </Tab>
  
  <Tab title="Medical Transfer Editor">
    ### Log a Medical Transfer
    
    <Steps>
      <Step title="Create New Transfer">

      </Step>

        Choose "Traslado Médico"

    </Steps>

    <Warning>

    </Warning>
  </Tab>
  
  <Tab title="Maintenance Team">

## Step 5: Understand Role-Based Access

SIGSAHO uses Role-Based Access Control (RBAC) to ensure users only access what they need:

### Access Control Example

```typescript
// Protected route configuration
const router = createBrowserRouter([
  {
    path: 'dashboard',
    element: (
      <RequireRole roles={ACCESS_STATS}>
        <Dashboard />
      </RequireRole>
    )
  },
  {
    path: 'configuracion',
    element: (
      <RequireRole roles={[SystemRoles.ADMINISTRADOR]}>
        <UsersSettingsPage />
      </RequireRole>
    )
  }
]);
```

## Step 6: Data Fetching & Real-Time Updates

SIGSAHO uses TanStack Query for efficient data management:

### Smart Caching Example

```typescript
// Dashboard metrics hook
export const useDashboardMetrics = () => {
  return useQuery({
    queryKey: ['dashboard', 'metrics'],
    queryFn: () => dashboardService.getMetrics(),
    staleTime: 5 * 60 * 1000,  // 5 minutes
    refetchOnWindowFocus: true, // Refresh when tab regains focus
  });
};
```

**Benefits:**
- Data cached for 5 minutes to reduce server load
- Automatic background refresh when cache expires
- Instant updates when switching between pages
- Optimistic UI updates for better UX

## Authentication & Session Management

### How Sessions Work

SIGSAHO uses a secure cookie-based authentication system:

```typescript
// Backend: Setting authentication cookies
const cookieOptions = {
  httpOnly: true,              // Not accessible via JavaScript
  secure: true,                // HTTPS only
  sameSite: 'strict',          // CSRF protection
  maxAge: 15 * 60 * 1000       // 15 minutes
};

res.cookie('accessToken', token, cookieOptions);
```

**Security Features:**
- Tokens stored in httpOnly cookies (immune to XSS attacks)
- Automatic token refresh every 15 minutes
- Session expires after inactivity
- All API requests authenticated via cookies

<Note>
  You won't see tokens in browser DevTools or localStorage - this is by design for maximum security.
</Note>

## Troubleshooting

<AccordionGroup>
  <Accordion title="I can't log in">
    - Verify username/email and password
    - Ensure Caps Lock is off
    - Try clearing browser cache and cookies
    - Contact your administrator to verify account status
  </Accordion>
  
  <Accordion title="I see 'Unauthorized' on a page">
    - You don't have permission for that module
    - Contact your admin to request the necessary role
    - Check with your supervisor if you should have access
  </Accordion>
  
  <Accordion title="Widgets won't load">
    - Check your internet connection
    - Refresh the page (Ctrl+R or Cmd+R)
    - Try logging out and back in
    - Contact IT if the issue persists
  </Accordion>
  
  <Accordion title="Form won't submit">
    - Look for red error messages below fields
    - Ensure all required fields (*) are filled
    - Verify data formats (dates, numbers, emails)
    - Check console (F12) for validation errors
  </Accordion>
</AccordionGroup>
